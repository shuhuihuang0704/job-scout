# Matching rubric

Use this guide when the user asks which listings best fit them.

## Separate constraints from preferences

- Hard constraints are conditions the user explicitly requires, such as city, work type, or minimum salary. Flag a listing that misses one instead of hiding the mismatch in a score.
- Preferences help order otherwise suitable results, such as a product area, company stage, or preferred work arrangement. Do not turn a preference into a rejection rule unless the user says so.
- If the user accepts internships, keep internship listings eligible and label them clearly. Do not infer seniority, degree requirements, or relocation flexibility.

## Use only known information

Compare the posting with the user's stated background only when they provide it or ask you to use a specific profile source. Treat absent information as unknown, not as a deficiency. Never invent experience, qualifications, product use, or achievements.

Explain the strongest match and the most important gap or unknown in plain language. Avoid numerical fit scores by default. If the user requests scores, state the scale and cite the criteria used for each score.
